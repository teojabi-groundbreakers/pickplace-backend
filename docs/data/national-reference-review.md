# 전국 기준정보 계층·대응 검토

검토일: 2026-11-09 · 원천 기준: 인구/상가202609, 공식 H 파일20261026

최종 후속: [T07 승인·게시 완료](national-reference-completion.md). 아래는 원래 reviewed-v1 검토본과 정책 확정 당시 기록이다. 기존 READY 검토본을 수정하지 않고 별도 release-v1을 승인·게시했다.

## 확정 정책 — 출장소 초기 제외

2026-11-09 사용자 확정: 이번 스냅샷의 출장소 관련76개 노드는 원본·코드·이력·검토 근거를 보존하고 초기 서비스의 지역 선택 목록에서는 제외한다. 현재 관할·중복 집계 범위가 미확인이라는 사실은 유지한다.

- 원본 노드와 원천 통계 참조를 삭제하지 않는다.
- 선택 가능 여부는 FALSE로 유지하고 일반 읍면동으로 자동 치환·합산하지 않는다.
- 이들 지역의 상세 지원은 추후 확장으로 분리한다. 출장소 관할 전수 검증 자체를 초기 서비스 공개의 필수 조건으로 두지 않는다.
- 승인 경로는 확정 정책 버전·원본 해시·명시 코드76개·비선택 상태·제외 근거가 일치하는 노드만 허용한다. 다른 BLOCKED/PENDING은 거절한다. 기존 READY 묶음은 변경하지 않고 최종 release-v1에 적용했다.

76개는 현재 원본 스냅샷의 건수다. 이후 자료에서 추가되는 노드는 같은 숫자나 이름 필터만으로 자동 승인하지 않고 다시 검토한다.

검토는 원본의 코드·명칭·소속·이력과 서비스 선택 계층의 일관성 확인이다. 법적 기관 유형 전수 인증·통계 경계 재배분·이용조건 승인·공개 게시와 구분한다. 기존 후보본을 수정하지 않고 `national-202609-reviewed-v1`이라는 새 묶음을 만든다.

## 계층 검토 기준

공식 H 파일은 시도명·시군구명·읍면동명과 코드/생성/말소일을 제공한다. 명시적 parentCode 파일은 아니므로 서비스 계층은 검증한 파생 관계로 기록한다. 코드 접두어만으로 확정하지 않고 공식 원문 경로와 부모의 역할을 함께 검사한다.

| 사례 | 확인 |
|---|---|
| 일반 읍면동 | 실제 공식 부모 노드가 존재하며 시도명·시군구명이 양쪽에서 같음 |
| 일반 시 산하 구 | 공식 시군구명 전체 경로와 유일한 도시 컨테이너가 일치함 |
| 시·도→화면 그룹 | 내부 시 컨테이너와 화면 그룹을 구분, 시·도 소속과 표시 경로 검사 |
| 세종 | 실제 중간 H10 `3611000000` 보존, 시군구 공란을 가짜 구 이름으로 채우지 않음 |
| 출장소 | 원문 보존, 관할이 확인되지 않은 후보는 선택 목록에서 제외 |

선택 계층의 누락·중복·부모 존재·역할·시·도 도달성·순환·표시명을 검사한다. 세종 자동 선택은 이번 검토에서 활성화하지 않았다. `4110500000`의 북부출장소, `5110500000`의 동해출장소처럼 시도명 필드 자체가 일반 시·도 명칭과 다른 행도 보류76개에 포함한다.

## 대응 검토 기준

1. 원본 파일 SHA256·크기와 기존 후보 묶음의 SHA256을 다시 확인한다.
2. 인구 원천H10은 공식 이력의 동일 코드와 원문 이름·시도/시군구·날짜 품질을 대조한다.
3. 상가8은 공식 이력의 고유 후보를 찾은 뒤 원천 시군구코드·시도명·시군구명·행정동명을 함께 대조한다.
4. 명칭은 코드 탐색 키로 사용하지 않는다. 동일 식별자·소속을 대조한 뒤 공백·가운뎃점·숫자 앞 서수 표기의 차이만 기록한다. 예: `홍제1동`과 `홍제제1동`을 양쪽에서 무조건 '제' 삭제하는 방식으로 비교하지 않는다.
5. 대응 근거는 새 릴리스의 mapping.evidence JSON에 원문명·공식명·원본 해시·정책 버전과 함께 저장한다. 기존 원천 참조 행과 후보 릴리스는 유지한다.

이 검토 결과는 이번 원천·공식 스냅샷 쌍에 한정된다. 앞으로의 모든8자리 코드를 뒤에00을 붙여 변환하는 규칙이나 영구적인 명칭 별칭표가 아니다.

## 변경일·과거 코드 예외

| 원천 | 코드→공식 H10 | 판정 |
|---|---|---|
| 인구 구지읍 | 2771026800→2771026800 | 생성일과 인구 기준일이2026-09-30으로 같아 `CHANGE_DATE_HOLD` |
| 상가 구지면 | 27710380→2771038000 | 말소일과 배포 기준일이2026-09-30으로 같아 `CHANGE_DATE_HOLD` |
| 인구·상가 고덕동 | 4122066000 / 41220660→4122066000 | 9월은 기록된 유효기간 내부,10월 분동 후 새 동들로 배분하지 않음 |

식별 대응 VERIFIED는 같은 지역을 가리킨다는 판단이다. `mapping.evidence.temporalStatus`가 `CHANGE_DATE_HOLD` 또는 `OUTSIDE_PERIOD_HOLD`이면 T13/T14에서 정상 통계 집계로 채택하면 안 된다. 서비스 통계의 별도 temporal_region_status로 이행하고, 적용 정책/근거를 함께 추적한다. 경계 변경일의 포함/제외 시각을 원문 날짜만으로 추측하지 않는다.

## 재현과 검증

현재 스크립트는 기존 후보 묶음과 검증한202609 원본을 대상으로 한다. 새 자료는 원천/정책을 다시 검토해야 한다.

```cmd
python -B -m unittest discover -s scripts -p test_review_national_reference.py
python -B scripts\review_national_reference.py --input 후보_JSON --sha256 후보_SHA256 --regions 공식원본폴더 --statistics 통계원본폴더 --version national-202609-reviewed-v1 --output 새_검토본_JSON
```

원본·기존 묶음 변경, 명칭/부모 충돌, 중복/모호 대응, 설명되지 않은 유형은 새 검토본 출력을 중단한다. 출력은 기존 파일을 덮어쓰지 않는다. Python10개 검사로 잘못된 코드·명칭·시도/부모·표시와 변경일 판정을 확인한다.

격리 MySQL에서 검토본 적재와3850/76 상태 분리·3837 선택 노드·7177 대응·변경일2건·구지면 과거 코드 보존·재실행을 검사한다. 실제 개발 DB 적용 결과와 최종 테스트 수는 검토 기록에 구분해 남긴다.

원본 H 자료 이용조건 검토는 여전히 PENDING이며 출장소76개도 BLOCKED다. 검토본은 READY로 저장하고 실제 승인·공개는 하지 않는다. `selectable=true`는 검토본 내부 후보의 자격이며 승인된 게시 포인터가 없으면 공개 목록으로 사용하지 않는다.

실행 결과: Java230건·Python10건 통과, 실패/오류/건너뜀0. 기존 개발 DB에 새 검토본을 release ID3/READY로 적재했고 기존 후보 ID1은 보존했다. 원천 참조7,177건과 업종332건은 재사용해 중복하지 않았다. 실제 게시 포인터는0건이다.
